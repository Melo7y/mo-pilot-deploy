# v0.1 → v0.2.0 正式版升级

**v0.2.0 是正式上线版本，前后端一起更新。** 升级起点为 v0.1（v0.1.0），数据库从 00008 升至 00011。

## 本版变化

- 工作台排期与甘特图：整理说明文字，支持中国放假与调休上班标识，已收录 2025、2026 年；未收录年份显示提示。
- 需求管理：新增需求人姓名与团队展示，支持需求软删除及相关筛选。
- 任务管理：维护当前投入人数，完善排期信息。
- 钉钉：个人账号绑定、管理端绑定查询及任务通知；启用时沿用钉钉 Compose 覆盖文件和企业配置。
- 界面：右上角用户入口、个人设置布局、手机显示和新 Logo。

## 1. 打包

在构建机或测试服务器的 `mo-pilot-deploy` 目录，使用最新脚本执行：

```bash
bash scripts/package.sh v0.2.0
```

不用填写 SHA 或迁移号。脚本自动获取三个仓库最新的远程 `main`，识别当前 Docker 平台，从后端源码识别目标迁移，再固定这些提交进行构建。不会切换你的分支或打包本地未提交的修改。三个仓库需位于同一父目录，前后端目录分别叫 `frontend`、`backend`，各自配置 `origin`。

如果当前部署目录仍是旧脚本，先获取新版脚本再执行，不必覆盖现有部署配置：

```bash
cd /home/melo/code/mo-pilot/mo-pilot-deploy &&
git fetch origin main &&
git show origin/main:scripts/package.sh > /tmp/mopilot-package.sh &&
bash /tmp/mopilot-package.sh v0.2.0
```

同一服务器打包和部署时无需指定平台。跨机器打包才在最后加目标平台，例如 `bash scripts/package.sh v0.2.0 linux/amd64`。代理沿用导出的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。

成功后输出 `Package ready`，默认目录是三个仓库父目录下的 `.scratch/packages/v0.2.0/`，包含：

```text
mopilot-images-v0.2.0.tar.gz
mopilot-deploy-v0.2.0.tar.gz
source.txt
SHA256SUMS
```

`source.txt` 自动记录实际提交、平台与迁移号。首次交付后保留这组产物；后续 main 有新改动时使用新的版本号，不覆盖同名镜像或旧升级包。

## 2. 停机升级

进入现有部署目录，按 [统一升级流程 B](README.md#b-前后端整套升级) 执行，只填写以下三个值：

```bash
TAG=v0.2.0
PACKAGE=../.scratch/packages/v0.2.0
EXPECTED_MIGRATION=00011
```

`PACKAGE` 可改为实际上传目录。流程会校验升级包、备份配置与数据库/附件、停机迁移、启动前后端。镜像统一为 `mopilot-api:v0.2.0` 和 `mopilot-web:v0.2.0`，清空前端独立镜像标签。保留原 Compose 项目名；已启用钉钉的环境继续使用 `-f compose.dingtalk.yaml`。

确认 API、Web、数据库健康且迁移达到 00011；强制刷新后检查登录、需求/任务、历史附件、甘特图和需求人列。使用钉钉时检查本人绑定及实际任务通知。2027 年放假调休数据待官方安排确认后另行更新。
