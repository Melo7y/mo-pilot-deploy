# 甘特图与需求人列：前端更新

适用于已完成 **v0.2.0-rc.1** 升级的测试服务器。本次只更新前端，无需更新后端或执行 `migrate up`。

包含：甘特图说明文字整理、2025/2026 中国放假调休标识、需求列表「需求人」姓名和团队。前端提交 `3c530b35f5ba891387aa41f2b3eb1384b5c35e6b`，验收镜像 `mopilot-web:v0.2-ui-3c530b3`。

## 1. 在测试服务器执行

沿用现有 `.env`、项目名和同级 `../frontend` 仓库；不需要切换当前 Git 分支。下面是当前使用的 `compose.yaml` 启动方式；如实际启动还使用了额外 `-f` 或 `-p`，先把它们加入脚本的 `dc()`。

```bash
cd /home/melo/code/mo-pilot/mo-pilot-deploy
git fetch origin docs/ui-acceptance-upgrade &&
git show origin/docs/ui-acceptance-upgrade:scripts/update-ui-20261015.sh > /tmp/mopilot-update-ui.sh &&
bash /tmp/mopilot-update-ui.sh
```

脚本先获取固定前端源码并在本机打包，成功后备份 `.env` 和 `compose.yaml` 到用户目录，再替换 `web`。构建期间服务继续运行，替换时网页短暂中断。构建如需代理，先按现有环境导出 `HTTP_PROXY`、`HTTPS_PROXY`；脚本会传入构建。

出现 **「更新完成」** 即可验收；报错时先处理错误，不继续手动启动全套服务。旧的 `v0.2.0-rc.1` 四文件升级包不包含本次修改。

## 2. 刷新并验收

强制刷新浏览器：需求管理出现「需求人」列；甘特图无缺失日期等说明文字悬浮在网格内，2026 年 10 月 1—7 日标「休」、10 月 10 日标「班」。2027 年尚未收录时会显示提示，待官方年度通知后补充数据并发布前端更新。

## 需要回退时

在 `.env` 将 `MOPILOT_WEB_IMAGE_TAG` 改为原前端镜像标签（原版为 `v0.2.0-rc.1`，脚本末尾也会打印原镜像），然后执行：

```bash
docker compose --env-file .env -f compose.yaml up -d --no-deps --no-build --pull never --wait --wait-timeout 120 web
```

之后整套版本升级或回滚时，先清空 `.env` 的 `MOPILOT_WEB_IMAGE_TAG`，再按统一 `MOPILOT_IMAGE_TAG` 更新。
